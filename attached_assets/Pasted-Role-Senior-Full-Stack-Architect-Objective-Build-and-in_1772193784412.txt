Role: Senior Full-Stack Architect.
Objective: Build and integrate the missing Partner App, Rider App, and Admin Dashboard into the existing Customer App prototype. Use a "Hub-and-Spoke" architecture where the Backend acts as the central coordinator.

1. The Partner (Pharmacy) App
Onboarding: Create a registration flow requiring Store Name, GST, Pharmacy License upload, and GPS location. Set status to PENDING_ADMIN_APPROVAL.

Order Management: * Implement a Loud Ringtone Alert for incoming orders.

Pharmacist Verification: A screen to view the Customer's uploaded prescription. The "Accept Order" button only unlocks after the pharmacist selects "Prescription Verified."

Inventory Control: A simple "In-Stock/Out-of-Stock" toggle for the 100 most popular medicines.

Substitute Logic: If an item is out of stock, allow the pharmacist to suggest a generic equivalent via the app.

2. The Rider App
Duty Toggle: A "Go Online/Offline" switch.

Acceptance Flow: Riders see a 60-second countdown to accept an order.

In-App Navigation: Integrated Google Maps showing the route to the Pharmacy first, then to the Customer.

Proof of Delivery: * Requirement A: Rider must enter a 4-digit OTP provided by the Customer.

Requirement B: For high-value orders, a "Photo at Doorstep" feature.

3. The Admin Dashboard (Web)
Approval Hub: A central list of all new Partner and Rider signups with document viewers to Approve or Reject them.

Live Order Map: A real-time view of all active orders, moving riders (GPS), and store locations.

Financials: Calculate and display:

Platform Commission (15–20%).

Total Store Payouts.

Rider Earnings + Tips.

Heatmaps: Show where customers are searching but not finding medicines to identify where to onboard more stores.

4. Shared Logic & Exceptions
The State Machine: Every order must transition through: PENDING → STORE_ACCEPTED → PREPARING → RIDER_ASSIGNED → IN_TRANSIT → DELIVERED.

Midnight Flush: At 23:59:59 daily, force-logout all users (except those with an active IN_TRANSIT order) and reset all Rider/Store statuses to Offline.

Push Notifications: Use Firebase (FCM) to sync all apps (e.g., when the store clicks "Ready," the Rider gets a ping immediately).

5. Payment & Splits
Implement a Wallet System for Riders and Stores.

Logic: On DELIVERED status, auto-calculate the split and update the respective virtual wallets in the database.
